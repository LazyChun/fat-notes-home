# 定时任务

> 「立即运行」是手动点一次，「定时任务」是让面板按时间表自己跑。它把**定时运行规则**（什么时候跑）、**面板里的工作流卡片**（跑什么）和**一条运行中的定时记录**（是否交给后台调度）串在一起，适合日报、巡检、同步、备份这类重复工作。

三件事分清楚，定时任务就不会「配好了却不跑」：

| 组成 | 在哪儿配置 | 作用 |
| --- | --- | --- |
| 定时运行规则 | 运行面板 → 定时运行规则 → 添加运行模式 | 名称、Cron 表达式、启用状态；从面板入口创建时自动绑定该面板 |
| 工作流卡片 | 面板画布上的思维 / 屏幕任务 / ETL DAG 块 | 到点后真正被执行的内容 |
| 定时运行记录 | 页面标签栏 ▶ 下拉 → 定时运行 → 选一条规则 | 激活开关：后台只调度有定时运行记录的面板 |

---

## 从哪里进入

| 入口 | 位置 | 适合做什么 |
| --- | --- | --- |
| 运行面板 | 左侧活动栏的**播放三角「运行」**图标 | 集中查看正在运行、已完成，管理全部定时规则 |
| 运行下拉菜单 | 页面标签栏右侧 **▶ 及其旁的小箭头** | 在具体面板上立即运行、激活某条定时规则、就地新建规则 |
| 命令面板 | `Ctrl + K` 搜索「运行」 | 快速跳转到运行面板 |

只有**含工作流卡片的面板**才显示 ▶ 按钮；普通图表面板没有可调度的工作流，也就不会出现这个入口。

![运行面板的「定时运行规则」页，红框标出侧栏入口与「添加运行模式」按钮](pathname:///fat-notes-home/img/instruction/schedule/zh/schedule-rules.png)

*运行面板分三页：正在运行 / 已完成 / 定时运行规则。红框分别是左侧「定时运行规则」与右上角「添加运行模式」。*

## 认识定时运行规则列表

规则列表是全部定时任务的台账：

| 列 | 说明 |
| --- | --- |
| 规则名称 | 自定义名称，建议写清频率与用途，例如「每日 09:00 经营日报」 |
| Cron表达式 | 五段时间表，格式「分 时 日 月 周」 |
| 执行次数 | 这条规则累计触发的次数，从 0 开始 |
| 面板名称 | 规则绑定的面板；显示 `[通用]` 表示未绑定具体面板 |
| 启用 | 开关，关掉即暂停该规则 |
| 操作 | 编辑（改名 / 改 Cron / 改启用）、删除（需确认） |

顶部还有三个筛选条件：**搜索规则名称**（支持拼音模糊匹配）、**搜索Cron表达式**、**选择面板**（多选）。规则多时，按面板筛选最省事。

---

## 创建一条规则

1. 打开一个含工作流卡片的面板，点标签栏 ▶ 旁的小箭头 → **添加运行模式**；或在运行面板的「定时运行规则」页点右上角 **添加运行模式**。
2. 在弹窗里填写名称与 Cron 表达式，确认「启用」为开。
3. 点**确定**保存，规则立刻出现在列表中。

![添加定时运行规则弹窗，红框标出规则名称、Cron表达式与启用](pathname:///fat-notes-home/img/instruction/schedule/zh/schedule-rule-modal.png)

*红框从上到下是：规则名称（必填）、Cron表达式（必填，含可视化选择器与输入框）、启用（默认打开）。底部是取消 / 确定。*

### 字段速查

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 规则名称 | 是 | 占位提示「请输入规则名称」；在下拉菜单、运行记录里都会显示 |
| Cron表达式 | 是 | 既可以直接输入，也可以用下方的可视化选择器拼；提示「格式: 分 时 日 月 周」 |
| 启用 | 否 | 默认开启；关闭后规则保留但不参与调度 |

可视化选择器会把表达式翻译成人话，例如 `0 9 * * 1-5` 显示为「每 周 在 一-五 在 9 : 0」；改下拉选项时，上方输入框里的表达式同步变化。

### 常用 Cron 表达式

| 表达式 | 含义 |
| --- | --- |
| `*/5 * * * *` | 每 5 分钟 |
| `0 9 * * *` | 每天 09:00 |
| `30 8 * * *` | 每天 08:30 |
| `0 0 1 * *` | 每月 1 日 00:00 |
| `0 9 * * 1-5` | 按周重复（界面显示为周一至周五 09:00，见下方周字段提示） |

只支持**五段**表达式与 `*`、`/`、`,`、`-` 这几种写法；秒级表达式、六段以上表达式以及 `?`、`L`、`W` 等扩展语法不会被识别。

## 让规则真正跑起来（最容易漏的一步）

新建规则只是登记了一张时间表。要让后台按点执行，还需要**在目标面板上激活它**：

1. 打开绑定了该规则、且含工作流卡片的面板。
2. 点标签栏 ▶ 旁的小箭头，展开运行菜单。
3. 在「定时运行」分组里点选这条规则。此时会生成一条**运行类型 = 定时**的运行记录，出现在「正在运行」列表里。
4. 保持应用运行；到点后，后台执行该面板内所有工作流卡片，画布上可以看到节点运行进度。

![页面标签栏的运行下拉菜单，红框标出「定时运行」分组与「添加运行模式」](pathname:///fat-notes-home/img/instruction/schedule/zh/schedule-board-menu.png)

*菜单从上到下：立即运行（运行中时变为停止运行）、「定时运行」分组（当前面板规则 + 通用规则，悬停会显示 Cron 表达式）、添加运行模式。分组里的规则点一下即激活；悬停约 2 秒还会出现编辑 / 删除图标。*

![定时任务的触发链路](pathname:///fat-notes-home/img/instruction/schedule/zh/schedule-mechanism.svg)

机制上有几点值得记住：

- 后台服务**每 30 秒**检查一次所有已启用规则，按**本机时间**匹配当前分钟，因此精度是分钟级。
- 只有「Cron 命中」且「该面板存在运行中的定时记录」时才会执行工作流；任一条件不满足都会跳过本轮。
- 同一个面板在 **55 秒**内最多触发一次，避免高频 Cron 把流程重复拉起。
- 执行的是面板内的**全部工作流卡片**（思维、屏幕任务、ETL DAG），进度通过 WebSocket 回传，不是重新刷新图表查询。

:::tip 想临时停一下？
两种都可以：在规则列表关掉「启用」（以后再打开即可），或在「正在运行」里点该记录的**取消**（结束这条定时运行，之后不再触发）。应用退出后调度随之停止，错过的次数不会补跑。
:::

## 查看运行记录

「运行面板」的另两页用来复盘。两页的**运行规则**列都很有用：定时记录显示规则名，点击会跳到「定时运行规则」页并自动按名称筛选；手动记录显示「立即运行」。

![正在运行列表，红框标出运行记录表格](pathname:///fat-notes-home/img/instruction/schedule/zh/schedule-running.png)

*列为面板名称 / 状态 / 运行规则 / 执行次数 / 开始时间 / 操作。定时类型的记录可以展开查看包含的工作流块，操作列的「取消」用于结束本次运行。*

![已完成列表，红框标出运行记录表格](pathname:///fat-notes-home/img/instruction/schedule/zh/schedule-completed.png)

*已完成页多了结束时间、持续时间，并可按「全部状态」筛选已完成 / 失败。定时触发的记录保留规则名与执行次数，便于回溯每次执行。*

| 页面 | 可以看到 | 典型用途 |
| --- | --- | --- |
| 正在运行 | 当前在跑的手动 / 定时记录、开始时间 | 确认定时任务是否已激活、取消运行 |
| 已完成 | 状态、开始 / 结束时间、持续时间 | 排查失败、评估流程耗时 |
| 定时运行规则 | 全部规则、启用状态、执行次数 | 改名、改频率、暂停、删除 |

## 典型组合

1. **每日经营日报**：面板里放一条 ETL DAG（查询昨日数据 → 计算指标 → 拼装文本 → 推送消息），建规则「每日 09:00 经营日报」`0 9 * * *`，从标签栏菜单激活。之后每天 9 点自动出报表。
2. **设备状态高频巡检**：规则 `*/5 * * * *` 绑定运维看板，流程负责拉取接口、写入数据源；注意流程耗时要明显短于间隔，避免任务还没跑完又到下一个触发点。
3. **每周备份**：用「日 / 月」字段表达固定日期更稳，例如 `0 0 1 * *` 每月首日跑备份流程；跑完到「已完成」页核对持续时间。
4. **多面板复用一个模式**：在运行面板直接新建的规则不绑定面板，面板名称显示 `[通用]`，会出现在各个面板的运行菜单里，适合当作「随手点一下」的预设模式；要自动执行，请从具体面板的「添加运行模式」入口创建。

## 注意事项

- **应用要保持运行**：调度器随后台服务启动，关闭应用后不会在后台继续跑，也不会补跑错过的次数。
- **面板里必须有工作流卡片**：图表、文本等普通块不会被定时执行；没有工作流卡片时，标签栏连 ▶ 按钮都不显示。
- **周字段存在语义差异**：可视化选择器按常见 Crontab 习惯解读（`0/7` = 周日、`1-5` = 周一至周五），后台匹配按 `0 = 周一 … 6 = 周日`。因此按周重复的规则，建议用可视化选择器生成后观察前几次实际触发时间，或改用「日 / 月」字段表达，以运行记录里的开始时间为准。
- **Cron 只到分钟级**：不要指望秒级触发；同一个面板还有 55 秒的最小触发间隔。
- **删除 ≠ 清理历史**：删除规则只删除规则本身，已有运行记录仍保留；只是暂时不用时，关「启用」比删除更安全。
- **和「时钟任务」块不是一回事**：组件面板「其他 → 时钟任务」是页面内的块级定时器，用于触发单个块的联动事件；定时运行规则面向整个面板的工作流，两者按需选用。
- **自动化有副作用**：工作流可能写库、调用接口或执行脚本，启用前先用「立即运行」验证一次，并确认目标数据源与凭据。
