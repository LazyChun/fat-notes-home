# 流程自动化

流程编辑器把一个任务拆分为若干可连接的**节点**。你在画布上拖拽节点、连线，就能编排出一套自动执行的工作流——不需要写代码，逻辑一目了然。一个流程通常由触发器、处理步骤、条件分支和输出动作组成。

## 内置节点类型

| 分类 | 代表节点 |
| --- | --- |
| 逻辑控制 | 条件分支、循环、迭代、等待、变量 |
| 数据处理 | 数据源查询 / 增删改、表达式、代码执行 |
| AI | 大模型调用、知识库检索、Agent |
| 外部交互 | HTTP 请求、屏幕自动化（鼠标 / 键盘 / 找图 / 找色）、浏览器自动化（Playwright） |
| 媒体处理 | 音视频转码、TTS 文字转语音、ASR 语音转文字、OCR 图片转文字 |

## 常见场景

- **定时查询数据库并生成报告**：每天早上自动跑一遍统计 SQL，结果写入笔记或推送通知。
- **表格数据清洗与汇总**：把散乱的表格数据按规则转换、去重、汇总。
- **调用 HTTP 服务并保存响应**：轮询接口状态，把返回结果存入数据库。
- **处理重复的桌面操作**：通过 OCR、键鼠模拟或浏览器节点，自动完成填表、导出等重复动作。
- **AI 接力处理**：把知识检索的结果交给大模型节点，自动生成摘要或周报。

## 一个具体例子

下面这条流程演示了最基本的用法——输入 Unix 时间戳，一键转换为可读时间：

```text
输入块（Unix 时间戳）→ 时间转换节点 → 结果写入文本块 + 系统通知
```

在输入块填入 `1790000000`，点击运行，结果块立刻显示 `2026-09-21 22:13:20`。同样的模式可以套用在日志清洗、编码转换、定时抓取等任务上。

流程还可以和看板联动：ETL DAG 本身也是画布上的一种块，可以和输入框、图表放在同一页，构成「输入 → 处理 → 可视化」的交互式小应用。

## 设计可靠流程的建议

1. **每个流程只负责一个清晰的目标**，复杂任务拆成多个流程组合。
2. **为外部调用设置合理的超时和失败分支**，网络请求不一定每次都成功。
3. **在修改数据前记录输入并验证处理结果**，给自己留一条可回溯的路径。
4. **先用测试数据运行，再连接正式环境**。

:::warning 自动化风险
屏幕自动化和数据写入可能产生不可逆操作。运行前应确认目标窗口、账户权限和数据备份。
:::
